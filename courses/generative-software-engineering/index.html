第一章 / 软件过程与过程模型
1.1 什么是软件过程开始阅读 ↗

从复习清单的完成勾选出发，认识开发活动、工作结果与反馈，配有起始项目和实践提示词。

1.2 从最简单的开发方式开始开始阅读 ↗

继续增加过滤功能，认识边写边改的适用条件，以及怎样检查对原有功能的影响。

1.3 将工作划分为阶段开始阅读 ↗

通过进度导出与导入理解阶段划分，认识瀑布模型，以及后期改变要求会影响哪些工作。

1.4 用快速原型确认需求开始阅读 ↗

操作导入原型，比较替换与合并，记录试用中的发现，并决定原型的后续处理。

1.5 增量与迭代开始阅读 ↗

分次增加导出和导入，根据反馈改进预览，检查已有功能与文件兼容。

1.6 风险驱动与螺旋模型开始阅读 ↗

尝试两台设备先后提交进度，比较覆盖、合并与版本检查，再依据结果安排后续开发。

1.7 统一过程与 RUP开始阅读 ↗

从同步实验走向功能交付，理解阶段与迭代，练习用例、分工和过程裁剪。

1.8 敏捷开发与持续反馈开始阅读 ↗

根据上传提示的使用反馈选择改动，理解敏捷价值观，以及怎样依据实际结果调整计划。

1.9 选择与调整软件过程开始阅读 ↗

比较需求、风险与协作条件，为具体任务选择开发安排，并根据条件变化继续调整。

III

生成式软件实战

从一个可以独立运行的应用开始，逐步处理多进程协作、独立部署和数据分析。

筹备中
  1. 基于单体架构的软件开发

    在一个应用中完成界面、业务处理与数据读写，运行、测试并部署整个项目。

  2. 分层架构与前后端应用开发

    分开界面、业务和数据访问职责，再通过 API 连接前端与后端，区分代码分层和部署分离。

  3. 基于 MVC/MVVM 的客户端开发

    在桌面、移动与 Web 界面中组织状态和交互，将界面更新与业务处理分开，并测试用户操作。

  4. 模块化单体的开发与演进

    按业务划分模块，约束模块间的调用和数据访问，在统一部署中维护清晰的边界。

  5. 可扩展 Web 架构下的软件开发

    运行多个应用实例，加入负载均衡、缓存与数据库复制，处理会话共享和数据更新。

  6. 事件驱动架构与异步应用开发

    将耗时工作交给队列和后台进程，再通过事件连接业务，处理重试、重复消费与执行顺序。

  7. 基于微服务架构的软件开发

    拆分需要独立部署的业务，明确各服务的数据归属，处理服务调用、超时、故障和跨服务协作。

  8. 云原生应用的开发与部署

    通过容器与编排管理应用，实践健康检查、弹性扩缩、滚动发布和运行观测。

  9. 采用 Serverless 架构开发应用

    使用托管计算和函数处理请求与事件，比较扩缩容、状态管理、执行限制和费用。

  10. 数据仓库与湖仓系统开发

    将业务数据接入分析系统，完成清洗、建模与查询，比较数据仓库、数据湖与湖仓的存储组织方式。

  11. 大数据架构下的批流处理系统开发

    并行处理历史数据，持续计算新到达的事件，处理任务调度、迟到数据、重放与结果校验。

同一个系统可以结合多种做法：单体应用也可以分层、使用队列并部署到云上；微服务也可以通过事件协作。实践中会结合具体需求，比较引入这些做法的收益与额外工作。
