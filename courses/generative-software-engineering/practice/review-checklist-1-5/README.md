# 复习清单

生成式软件工程 / 1.5 增量与迭代

当前项目支持勾选、取消、本地保存、未完成过滤和数量显示，还没有导出与导入功能。完成记录使用独立名称 gse-review-checklist-1-5。

你可以将项目解压到自己的工作目录，通过本地静态服务器运行。如果你的电脑已经安装 Python，可以执行 `python -m http.server 8000`，再访问 http://localhost:8000。修改前，你需要先尝试已有操作，确认它们正常运行，再保存一份原始代码。

你可以先安排两个版本：第一版增加下载进度文件的功能，第二版再增加完整的替换导入。编程助手可以根据 prompts.txt 中的提示词整理计划和修改代码，你需要阅读它的修改、运行页面，并保留每版的代码与实际测试结果。以后邀请别人试用时，如果发现预览容易引起误解，再根据具体困难改进。

下载按钮的点击事件需要调用生成进度文件的函数，再触发浏览器下载。文件沿用 1.3 中的格式：formatVersion 为 1，progress 数组包含全部三个编号，以及布尔类型的完成状态。程序应读取完整清单，包含被过滤隐藏的条目，下载时不修改当前记录。

替换导入的代码可以拆成多个任务分别编写，但文件校验、预览、取消、确认和失败处理共同组成完整功能，交付时不能省去其中一部分。确认前不修改记录，保存成功后才更新当前状态与界面。

使用者可能把第一版下载的文件留到第二版再导入，所以后写出的导入代码必须能读取先前生成的文件。你需要保留第一版实际下载的文件，第二版完成以后用它测试恢复进度，同时分别尝试 fixtures 中的有效与无效文件。

fixtures/valid-progress.json 为合法数据，其余文件分别包含 JSON 不完整、版本不支持、布尔类型错误、编号重复、未知编号和缺少条目的问题。错误文件应当拒绝，且不能改动原记录。

如果你已经实现了导入功能，就先保留已有工作，测试旧文件能否读取，再根据实际试用中遇到的困难决定是否改进预览。合并选项是否需要增加，也要先与使用者讨论。

提示词位于 prompts.txt。你需要分别记录每版能做什么、哪些测试已经执行、哪些操作仍待邀请使用者尝试。Git 恢复代码以后，浏览器中已经被覆盖的进度不会自动恢复，因此修改导入规则或数据结构以前，还需要另外保留进度备份。
