# 复习清单

生成式软件工程 / 1.3 将工作划分为阶段

当前项目支持独立勾选、取消、本地保存、未完成过滤和数量显示，还没有导出与导入功能。完成记录使用本地存储名称 `gse-review-checklist-1-3`，与前两节项目分开。

请在自己的工作目录中解压，通过本地静态服务器打开 index.html。如果已经安装 Python，可以执行 `python -m http.server 8000`，再访问 http://localhost:8000。也可以使用编辑器提供的静态预览服务器。

修改前，请检查原有功能并保存原始代码。然后依次完成并检查功能要求、文件格式与处理方案、代码实现，以及完整操作结果。提示词位于 prompts.txt。

本次导出全部三项的完成状态。导入采用替换规则，先完整检查，再对照当前状态与文件状态。确认前不能改动记录；取消、文件错误或保存失败时保留原状态。只有保存成功，才更新当前状态和界面。

为了区分以后可能变化的文件结构，文件使用 formatVersion 标明格式版本，当前版本为数字 1。progress 数组保存三项内容的记录，用 id 表示编号，用 completed 保存布尔状态。

由于清单包含固定的三项内容，文件需要保存 r001、r002、r003 的状态。导入时检查编号是否齐全、是否重复，以及是否出现其他编号。打开过滤后，页面会隐藏已完成项，完整清单仍然保留它们的数据。导出需要读取全部三项数据。

fixtures 目录提供以下检查文件：

- valid-progress.json：合法文件，r001 和 r003 完成，r002 未完成。
- invalid-json.json：JSON 内容不完整。
- invalid-version.json：格式版本为 2，本次不支持。
- invalid-boolean.json：将布尔值写成字符串。
- invalid-duplicate.json：编号重复。
- invalid-unknown-id.json：出现清单中没有的编号。
- invalid-missing.json：缺少条目。

无效文件都应拒绝，且不能改变当前或已经保存的完成状态。检查以前，请先在页面上设置与导入文件不同的状态，便于观察取消与替换是否正确。

可以在另一台设备运行项目，检查导出的文件能否迁移进度。也可以先在两个终端中分别运行 `python -m http.server 8000` 和 `python -m http.server 8001`，通过两个端口得到独立的浏览器存储。在同一地址打开两个标签页会共用本地存储，不能代替这项检查。

请保留实际检查步骤与结果。没有执行的检查应标为待确认，不能写成通过。
