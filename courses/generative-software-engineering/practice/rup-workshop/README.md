# 从同步实验安排后续开发

生成式软件工程 / 1.7 统一过程与 RUP

在解压目录中执行 `python -m http.server 8000`，然后访问 http://localhost:8000/sync-lab/。也可以使用编辑器提供的静态服务器。

sync-lab 沿用了 1.6 的同步冲突实验。电脑记录、手机记录与共享记录都保存在当前页面内存中，提交由页面中的函数完成。刷新页面后恢复初始状态。服务端保存与真实设备间的网络传输，需要在后续开发中实现和验证。

选择使用情况与提交方式以后，点击“模拟电脑端修改并提交”。共享记录更新后，再点击“模拟手机端勾选并提交”，核对共享记录和手机记录中各项的状态。每组操作结束后，点击“恢复当前场景”，再选择下一种提交方式。分别尝试两种使用情况下的三种提交方式，将实际结果填写到 experiment-record.md。

接着，在 use-case.md 中描述使用者为在手机上继续复习，与清单进行交互的过程。正常读取与读取失败分别记录，本机有未上传修改时的处理需要根据讨论结果填写。phase-plan.md 用来记录四个阶段的目标。选择一项需要验证的做法以后，用 iteration-plan.md 安排具体工作，再根据实际操作更新 review.md。development-case.md 用来记录项目的过程裁剪：哪些活动需要保留，哪些重复内容准备删去或合并。每项决定都要说明具体用途，以及以后由谁维护相应记录。

模板中的运行结果与评审决定留待实际工作后填写。如果独自实践，可以先承担网页与服务端两侧的计划工作，并注明当前有哪些结果已经运行验证。需要使用者参与的讨论保留为待讨论。

prompts.txt 提供了三段实践提示词。修改自己的清单以前，先保存当前代码和进度备份，确认备份能够读取。
