# 同步冲突实验

生成式软件工程 / 1.6 风险驱动与螺旋模型

你可以在本目录执行 `python -m http.server 8000`，再访问 http://localhost:8000。页面通过 JavaScript 模块加载实验代码，需要通过静态服务器访问。

电脑记录、手机记录和共享记录都保存在当前页面内存中。提交操作由页面中的函数完成，复习清单原有的浏览器存储与这些实验数据分开。刷新实验页面以后，三份记录恢复初始状态。

页面提供两种使用情况：

1. 使用者先在电脑上完成课堂笔记，再在手机上完成矿物识别。我们希望共享记录保留两项内容的完成状态。
2. 使用者先在电脑上取消课堂笔记的勾选，再在手机上完成矿物识别。我们希望共享记录保留课堂笔记未完成、矿物识别已完成的状态。

选择使用情况和提交方式以后，先点击“模拟电脑端修改并提交”。共享版本会从 7 变为 8。接着点击“模拟手机端勾选并提交”，手机会根据原来的第 7 版数据提交修改。核对各项状态以后，你可以恢复当前场景，再换一种提交方式比较结果。

`sync-core.js` 中的 `submitProgress` 负责接收提交。它根据所选规则更新共享记录，或者因基础版本过旧而拒绝写入。`lab.js` 负责按钮事件，并将提交结果显示到页面上。

版本检查拒绝手机的提交以后，共享记录保持电脑上传后的状态。手机上矿物识别的完成记录仍然留在本机，后续还需要读取最新记录、解决冲突并再次提交。这些后续操作需要另外实现和测试。

准备实验时，在 `risk-register.md` 中说明可能发生的覆盖问题。实际操作以后，把每组结果填写到 `experiment-record.md`，未操作的情况保留为待执行。接着，根据实际结果完成 `decision.md`，说明是否继续开发同步，以及接下来的开发周期准备解决什么问题。`prompts.txt` 提供了可以交给编程助手的提示词。
