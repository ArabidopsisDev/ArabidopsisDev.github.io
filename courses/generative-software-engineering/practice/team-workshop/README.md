# 第二章 / 具体开发方法与团队协作

2.1 根据使用需要整理完整工作与验收条件。
2.2 依据这些工作安排 Scrum 的目标、计划、完成标准与评审。
upload-lab 保留手动上传的页面实验，可以用于观察已有行为。

## 运行

在解压目录打开终端，运行：

```sh
python -m http.server 8094
```

浏览器访问 http://localhost:8094/upload-lab/ 。
如果端口已经被占用，可以改用其他空闲端口。
实验中的记录保存在当前页面内存中，刷新会恢复起点。

当前代码支持手动上传、版本比较与拒绝旧版本提交。
上传前预览尚未实现，实际服务的网络请求与保存需要在业务项目中另外验证。
准备安排上传预览时，先讨论行为，并将未实现的部分标为待实现。

## 整理工作

requests.md 记录实际使用需要与待讨论问题。
work-items.md 记录完整改动，acceptance.md 写明具体操作与预期结果。
product-backlog.md 记录目标与准备采用的工作顺序，顺序需要与相关成员讨论。

prompts-2-1.txt 保存 2.1 的三段提示词。
实际回答与运行结果在取得以后填写。

## 安排一次 Sprint

在 sprint-plan.md 记录周期、目标、选入工作与分工。
done.md 记录团队共同采用的完成标准。
使用者反馈与软件结果填入 sprint-review.md。
协作中的实际遗漏与准备改变的做法填入 retrospective.md。

prompts-2-2.txt 保存 2.2 的三段提示词。
尚未进行的活动保留为待执行，案例中的拟议安排与实际决定分开记录。
